## 四、P1 数据底座（约 1 天）

### 4.1 Mock 内部系统 `services/mock_internal`（:8210，FastAPI + MySQL `office_oa`）

**OA 模块（会议室）**

| 接口 | 说明 |
|---|---|
| `GET /oa/rooms` | 房间列表（楼栋/楼层/容量/设备） |
| `GET /oa/availability` | 按时段查可用（building/floor/date/start/end/capacity_min） |

| `POST /oa/bookings/{id}/reschedule` | 改期：先定新再放旧 |
| `POST /oa/bookings/{id}/cancel` | 取消：释放时段 |
| `GET /oa/bookings/my` | 我的预订 |
| `GET /oa/reports/room_usage` | 利用率聚合（V3 用，接口先留） |

**资产模块（动态可用状态）**

| 接口 | 说明 |
|---|---|
| `GET /asset/availability` | 按类别/keyword 实时可借状态（V2 用，接口先留） |

## 七、P4 Router + SSE + 最小前端（约 1~1.5 天）

### 7.1 Router（`backend/core/router.py`）

- 规则前置：问候/感谢/闲聊模板直答；“要人工/超范围”→ 兜底池 + 引导（零 Token）
- LLM 意图 JSON：`{intents, user_queries, slots, follow_up_message, confidence}`；解析先剥 ```json 再 loads，失败回退追问
- 槽位检查：会议域槽位（building/date/start/end/capacity）；**追问 ≤ 2 轮**，超限进兜底池
- 多意图：逐个处理再汇总（V1 串行）
- 兜底池写入：`unresolved_requests`（原因分类：超范围/超限/失败）

### 7.2 编排与出口

- `orchestrator.py`：A2A 调度（带工号/角色/上下文）→ 状态分流（completed / input-required / failed）→ 结果 LLM 口语化
- `api/v1/chat.py`：`POST /api/v1/chat/stream`（SSE：routing / progress / token / card / meta / done）
- `api/v1/auth.py`：JWT 登录（种子账号）；`api/v1/messages.py`：站内信读取（V1 建表 + 接口，V3 启用提醒任务）
- 前端：登录页 + 统一聊天页（意图卡 / 房间卡 / 预订卡 / 我的预订 / 追问气泡）+ 我的预订视图；SSE 解析复用 `useSSEChat`

### 7.3 意图评测（冷启动）

- 会议域评测集先 60 条（正常 / 模糊 / 越界 / 多意图四类）
- `scripts/eval_intent.py` 输出：准确率 / 槽位抽取率 / 混淆矩阵（【待实测】跑完填数）

### 7.4 V1 最终验收（逐条验收）

| # | 场景 | 断言 |
|---|---|---|
| 1 | “明天下午 3 点 A 栋有哪些空会议室？” | 返回实时列表（不落库） |
| 2 | “帮我订个 10 人的会议室” → 追问 → 补齐 | 追问合规、落单成功、有凭证 |
| 3 | 并发抢订同一时段 | 仅一人成功，另一人收到备选提示 |
| 4 | “改到 4 点” / “取消掉” | 原时段释放、状态正确 |
| 5 | “我明天有哪些会？” | 返回本人预订 |
| 6 | 越权：取消他人预订 | 拒绝 + 审计记录 |
| 7 | 链路日志 | 意图→路由→A2A→MCP→OA 全链路可追溯 |
